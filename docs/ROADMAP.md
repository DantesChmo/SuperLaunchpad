# Roadmap

Состояние на 2026-10-22: вышла **1.1.0** (удаление приложений в Корзину из режима редактирования).

Правило: **одна фича — один минорный релиз.** Фиксы и мелкие улучшения без новой функциональности идут патчами (`1.N.x`) между минорами. Ломающая модель раскладки фича — мажор.

Размер: **S** — до дня, **M** — пара дней, **L** — сначала `architect`, потом код.

## 1.2.0 — Контекстное меню

Правый клик по иконке и папке. Сейчас все действия спрятаны за jiggle-режимом, а правый клик — первое, что пробует пользователь мака.

- Приложение: **Открыть**, **Показать в Finder**, **Переместить в Корзину** (диалог из 1.1.0; системным приложениям пункт недоступен).
- Папка: **Открыть**, **Переименовать**, **Упорядочить по имени**, **Распустить папку** (приложения встают на её место в сетке).
- **Редактировать раскладку** — вход в jiggle-режим.
- Клики с модификаторами: `⌘`-клик запускает приложение, не закрывая лаунчер (чтобы открыть несколько подряд), `⌥⌘`-клик — Показать в Finder.
- VoiceOver: те же действия как accessibility actions.

## 1.3.0 — Скрытые приложения

Убрать из сетки, не удаляя: helper'ы, агенты, дубли, приложения, которые запускаются только из Dock.

- **Скрыть** в контекстном меню и в jiggle-режиме.
- Settings → **Скрытые приложения**: список с кнопкой «Вернуть».
- Поиск находит скрытые приложения, с пометкой.
- Миграция: колонка `isHidden` в `appEntry`; скрытое приложение не занимает место в сетке.

## 1.4.0 — Новые приложения

Сейчас новое приложение молча встаёт в конец последней страницы, и его приходится искать.

- **Синяя точка** у новых приложений, как в системном Launchpad; пропадает после первого запуска из лаунчера.
- Settings → **Куда класть новые приложения**: в конец / в папку по категории (если такая папка есть) / в папку «Новые».
- Миграция: флаг «новое» в `appEntry`; при первом запуске SuperLaunchpad новыми ничего не помечается.

## 1.5.0 — Запущенные приложения

- **Точка под иконкой** у запущенного приложения, как в Dock. `NSWorkspace.runningApplications` и уведомления о запуске/завершении.
- В контекстном меню запущенного: **Завершить**, с `⌥` — **Завершить принудительно**.
- Перемещение в Корзину из 1.1.0 предлагает завершить приложение, вместо отказа.

## 1.6.0 — Умный поиск

Поиск — основной способ запуска у опытных пользователей. Сейчас он ищет только по подстроке в имени.

- Нечёткое совпадение и по первым буквам слов: `vsc` → Visual Studio Code, `sysset` → System Settings.
- Поиск папок по названию: папка в результатах открывается по `Return`.
- Ранжирование: точное начало имени, потом частота запусков (счётчик запусков в БД).
- *Опция:* при пустом поиске первыми показывать часто запускаемые.

## 1.7.0 — Сброс и перенос раскладки

Раскладка — это порядок иконок, страницы, папки с названиями и скрытые приложения. Её собирают руками часами, а сейчас с ней можно сделать только одно — удалить `apps.db` и начать с нуля. Релиз закрывает три случая:

- **«Хочу начать заново».** Settings → **Сбросить раскладку**, с выбором, как разложить заново:
  - как в системном Launchpad (если его база есть на маке — на Tahoe её нет);
  - по категориям, как при первом запуске на Tahoe;
  - всё по алфавиту, без папок.
- **«Боюсь сломать».** Settings → **Сохранить раскладку в файл** и **Загрузить из файла**. Перед любым сбросом файл сохраняется автоматически, так что сброс можно отменить.
- **«Новый мак».** Тот же файл открывается на другом маке: приложения, которые там есть, встают на свои места и в свои папки; остальные пропускаются; новые для раскладки приложения уходят в конец.

Формат — JSON с bundle ID, страницами и папками; иконки в файл не попадают, они берутся с мака, где файл загружают.

## 1.8.0 — Мультивыделение

В режиме редактирования выбрать несколько иконок и работать с ними разом.

- Клик по иконке в jiggle-режиме ставит галочку; `⌘`-клик и рамка мышью — тоже.
- Перетаскивание группы: иконки едут стопкой, встают подряд на месте броса или в папку.
- Действия над группой: **В новую папку**, **Скрыть**, **Переместить в Корзину**.
- **До начала:** разрезать `LaunchpadViewModel` (890 строк) на модели поиска, редактирования/drag и удаления — патчем без изменения поведения. Drag-логика и так самая сложная, групповой drag туда же не влезет.

## 1.9.0 — Свои иконки

- Своя картинка для приложения: перетащить файл на иконку в режиме редактирования или «Сменить иконку…» в контекстном меню; «Вернуть стандартную».
- Обложка папки: эмодзи или картинка вместо мини-сетки 3×3.
- Хранится в БД отдельно от иконок приложений, переживает пересканирование и попадает в файл раскладки из 1.7.0.

## 1.10.0 — Внешний вид

- Фон: сила размытия, затемнение, вариант «размытые обои рабочего стола».
- Подписи под иконками: размер, «скрыть подписи».
- *Спайк внутри релиза:* иконки в стиле Tahoe (тёмные / прозрачные / тонированные по системной настройке). Если `NSWorkspace` не отдаёт нужный вариант — записываем вывод, в релиз не берём.

**Вывод спайка (macOS 26.6, SDK 27.0).** Новый API не нужен: `NSWorkspace.icon(forFile:)` уже отдаёт вариант, выбранный в System Settings → Appearance → Icon & widget style, и для приложений Apple, и для сторонних (проверено на Notes, Finder, Telegram). В проверке стиль задавался только тестовому процессу, через скрытый глобальный ключ `AppleIconAppearanceTheme` (`RegularDark`, `ClearDark`, `TintedLight`, …) в argument domain. Иконка получалась тёмной, прозрачной или тонированной. Системную настройку пользователя не трогали.
- Чего нет: публичного способа запросить вариант в обход системной настройки. В заголовках `NSWorkspace`, `NSImage`, `NSAppearance` и LaunchServices нет ничего нового про иконки. `performAsCurrentDrawingAppearance` с `.aqua` / `.darkAqua` и `Bundle.image(forResource:)` дают обычную иконку. Нет и публичного уведомления о смене стиля. Поэтому отдельная настройка «свой стиль иконок в SuperLaunchpad» невозможна без приватного ключа, и её нет.
- Что взяли в релиз (без переключателя, потому что выключать нечего): иконки в БД — PNG, снятые при сканировании, и раньше новый стиль появлялся только после перезапуска. Теперь `IconStyleProbe` при каждой активации приложения рисует иконку Finder в 32 px. Если она изменилась, запускается пересканирование, и оно перезаписывает `iconData` всех приложений в новом стиле.
- Не проверено вживую: подхватывает ли уже запущенный процесс смену стиля в System Settings без перезапуска (меняется глобальная настройка, её нельзя было трогать). Если не подхватывает, проба просто ничего не заметит, и стиль применится при следующем запуске, как раньше.

## 1.11.0 — Клавиатурная навигация по сетке

Сейчас стрелки только листают страницы; иконки выбираются стрелками лишь в результатах поиска.

- Стрелки двигают фокус по иконкам, на краю — на соседнюю страницу; `Return` открывает приложение или папку; внутри папки — то же самое.
- Заметное кольцо фокуса, с учётом Increase Contrast.
- В 2.0.0 навигация подстраивается под выбранный размер сетки.

## 2.0.0 — Размер сетки и иконок

Мажор: меняется сама модель раскладки. Сейчас 7×5 зашито в константу, а страница — это ровно 35 мест. 7×5 мелко на 13" и пусто на 32".

- Settings: колонки × ряды (например от 5×4 до 9×7) и масштаб иконок, с живым предпросмотром.
- При смене размера страницы переразбиваются: порядок и папки сохраняются, приложения перетекают между страницами. Возврат к прежнему размеру возвращает прежнюю раскладку, а не перемешанную.
- Сетка папки (4×3) тоже настраивается или масштабируется вместе с основной.
- `Grid` перестаёт быть статикой: затрагивает `GridLayout`, `GridGeometry`, `LayoutMetrics`, drag, edge paging, `pageIndex` в БД и формат файла раскладки из 1.7.0 (версия формата, старые файлы загружаются).
- Проект от `architect` до кода; миграция БД с проверкой на копии реальной базы.

## Идеи без решения

Не в плане, пока не станет понятно, стоит ли и можно ли:

- **Бейджи уведомлений** на иконках (счётчики Mail, Telegram, как в Dock). Публичного API нет; похоже, только через Accessibility API к Dock — это лишнее разрешение. Сначала спайк.
- **Строка избранного** внизу, одинаковая на всех страницах, как Dock на iPhone.
- **Поиск за пределами приложений**: разделы Системных настроек (Wi-Fi, Bluetooth, …), калькулятор в строке поиска.
- **URL-схема и Команды**: `superlaunchpad://show`, `superlaunchpad://search?q=…`, действия для приложения «Команды» — чтобы открывать лаунчер из Raycast, BetterTouchTool и т. п.

## Патчи между минорами

Без новой функциональности, выпускать по мере готовности:

- **Чёткие иконки на Retina.** Иконки ужимаются до 128×128 px (литерал в `AppEnumerator`), а на экране они ~90–110 pt, то есть нужно ~200 px. Хранить 256 px, пересобрать кеш миграцией. Самый заметный визуальный дефект — **первым патчем**.
- **`~/Applications`** в сканировании и в `AppDirectoryWatcher`: туда Safari и Chrome кладут веб-приложения.
- **`AGENTS.md`**: «Known limitations» утверждает, что поиска, DnD и создания папок нет; в project map не хватает половины файлов. `/sync-agents-md`.
- **Разрезать `LaunchpadViewModel`** — перед 1.8.0 (см. выше).
- Swift 6 language mode / strict concurrency (сейчас `SWIFT_VERSION = 5.0`).

## Готовность релиза

1. Фича смержена, тесты на неё зелёные на CI (UI-тесты — только на CI).
2. Полная регрессия один раз перед тегом, не после каждого шага.
3. Запись в `CHANGELOG.md`, тег `v1.N.0`, Sparkle и Homebrew обновляются из workflow.

## Сознательно не делаем

- **Новые способы открыть** (значок в Dock, горячий угол, перехват F4) — отказались, хватает хоткея и pinch.
- **Локализация интерфейса** — английского достаточно.
- **Developer ID и нотаризация** — аккаунта разработчика нет; остаёмся на ad-hoc и «Open Anyway».
- **Mac App Store** — песочница ломает глобальные мониторы жестов и перемещение в Корзину через Finder.
- **Синхронизация через iCloud** — сначала файл раскладки (1.7.0), дальше по спросу.
